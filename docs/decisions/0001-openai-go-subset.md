# 0001: Port a subset of openai-go v3.98.0, with its Azure add-on

Status: Accepted (owner, 2026-11-09, through the lead). Drafted by Xo
Azure 1.

## Context

Azure OpenAI from Go is two modules: OpenAI's own client,
`github.com/openai/openai-go/v3`, sends the requests, and
`github.com/Azure/azure-sdk-for-go/sdk/ai/azopenai` adds Azure's
request and response types (On Your Data, content filter results). The
xo-lang/azure repo ports `azopenai` v0.9.0's types, but Xo has no
client to send them with, so Xo programs cannot call Azure OpenAI.

openai-go v3.98.0 is 232k Go lines, generated by Stainless, under the
Apache License 2.0 (Copyright 2026 OpenAI; no NOTICE file). The azure
repo is MIT, so the port gets its own repository.

## Decision

1. **Where.** A new repository, `github.com/xo-lang/openai`, licensed
   under the Apache License 2.0 (LICENSE is openai-go's text). Each
   ported file carries OpenAI's copyright and a note that it was
   changed from the original (Apache 2.0, section 4(b)); NOTICE.md
   names the source and version. Private until its first release and
   check-public pass, then public as xo-lang/aws and xo-lang/azure are.
2. **Pin.** openai-go v3.98.0. Later versions follow the azure repo's
   refresh process (vectors re-run against the new release, drift
   recorded).
3. **First slice.**
   - The client and its options (`option`): base URL, API key and
     organization and project headers, extra headers and query values,
     max retries, request timeout, middleware; Go's retry rules
     (`x-should-retry`, `retry-after-ms`, `retry-after`, 408, 409, 429
     and 5xx, its backoff), its `User-Agent` and `X-Stainless-*` headers,
     and its error type (status, request, the API's `error` object).
   - Chat completions: create, the streamed form (server-sent events,
     ending at `[DONE]`), and Go's stream accumulator for content and
     tool calls. Stored completions (list, retrieve, update, delete,
     messages) only if they come cheap in the same slice.
   - Embeddings: create, with Go's base64 float decoding.
   - The models these need (`shared` and `shared/constant` parts), as
     Xo structs and enums; Go's `param.Opt` and omitted-versus-null
     fields as Xo options, written to the JSON Go writes.
   - The Azure add-on, as Go's `azure` package: `with_endpoint(endpoint,
     api_version)` (the `/openai/deployments/<model>/...` path rewrite
     and `api-version` query), `with_api_key` (the `Api-Key` header),
     `with_token_credential` (azcore's bearer token policy, default
     scope `https://cognitiveservices.azure.com/.default`), and
     `with_unsafe_allow_http`.
4. **Dependencies.** Go's `azure` package imports azcore (the
   TokenCredential, the bearer token policy and the pipeline), not
   azidentity. So `xo-lang/openai`'s `azure` package requires the
   azure repo's root module (`github.com/xo-lang/azure`, which holds
   azcore), and the caller passes any credential (azidentity's
   included). `xo-lang/azure/ai/azopenai` (its own module) then
   requires `xo-lang/openai`. The module graph has no cycle, so the
   add-on stays where Go puts it.
5. **Streaming** goes through azcore's server-sent events reader (the
   azure repo's port of azcore v1.24.0 `streaming/sse.go`), if its
   behavior matches openai-go's `packages/ssestream` on the vectors;
   where they differ, openai-go's rules win and the port has its own
   reader.
6. **Vectors.** A Go program runs openai-go v3.98.0 against a local
   fake server (loopback only) and prints every request (method, URL,
   headers with volatile values masked, body) and every result or
   error; Xo replays the same calls against the same fake. Never a
   real OpenAI or Azure endpoint, and no real key.

## Deferred

The Responses API (41k Go lines), assistants, threads and the other
beta APIs, audio, images, files and uploads, batches, fine tuning,
vector stores, moderation, models, containers, the admin APIs,
realtime and websockets, webhooks, the Bedrock and other provider
packages, and `azopenai`'s re-ported helpers that need the client.
Each is its own later slice, by user need.

## Consequences

- One more public repository to check before each push
  (check-public, gitleaks).
- The azure repo gets a pointer decision naming this one, and
  `ai/azopenai`'s README stops saying the client is missing once the
  first slice is released.
